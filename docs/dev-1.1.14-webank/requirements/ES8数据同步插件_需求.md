## 一、需求概述 【核心】

### 1.1 需求名称

ES8数据同步插件

### 1.2 需求背景

#### 业务背景
随着Elasticsearch 8.x的发布，越来越多的用户开始升级到ES8以获得更好的性能、安全性和新特性。然而，Exchangis现有的DataX Elasticsearch Writer插件基于ES6的`elasticsearch-rest-high-level-client 6.7.1`开发，无法连接ES8集群。

#### 痛点分析
- **兼容性问题**：ES6的高级别客户端与ES8服务器不兼容，连接时会报错
- **升级障碍**：用户无法将数据同步到新部署的ES8集群
- **迁移风险**：如果直接升级现有ES6插件，可能破坏正在使用ES6的现有用户
- **技术债务**：ES6的客户端已经被废弃，官方推荐迁移到新的Java API Client

#### 用户诉求
来自业务部门的数据团队反馈：
- 新的搜索分析平台已部署ES8.16.1，需要将MySQL业务数据同步到ES8
- 现有ES6插件连接ES8失败，错误信息：`This client version cannot communicate with this cluster`
- 不希望影响现有的ES6数据同步任务
- 期望配置方式与ES6插件相似，降低学习成本

### 1.3 需求目标

#### 核心目标（P0）
1. **功能实现**：开发独立的ES8 Writer插件，支持从MySQL、Hive、HDFS、CSV等数据源读取数据并写入ES8
2. **性能达标**：批量写入性能≥5000条/秒，多线程并发≥10000条/秒
3. **完全隔离**：ES6和ES8插件完全独立，可同时部署使用，互不影响
4. **稳定可靠**：具备完善的错误处理、重试机制和脏数据管理

#### 期望目标（P1）
1. **易用性**：配置参数与ES6插件保持相似，降低用户学习成本
2. **可观测性**：提供详细的同步统计信息和日志记录
3. **扩展性**：为未来支持ES8新特性（如向量搜索、AI集成）预留接口

#### 可选目标（P2）
1. **高级功能**：支持ES8特有的分布式追踪、异步搜索等新特性
2. **性能调优**：提供更精细的性能调优参数（如批量大小动态调整）

### 1.4 需求范围

#### 边界定义

| ✅ 包含（In Scope） | ❌ 不包含（Out of Scope） |
|-------------------|------------------------|
| ES8 Writer插件（写入ES8） | ES8 Reader插件（从ES8读取） |
| 支持ES 8.x全系列（8.0-8.16.1+） | 支持ES 7.x及以下版本 |
| 基础认证（用户名/密码） | SSL/TLS加密、PKI认证、OAuth认证 |
| 基本数据类型 + 复杂类型（nested/object/vector） | join等高级类型 |
| 简单字段映射 + 复杂嵌套映射 | 父子关系映射 |
| 批量写入、多线程并发 | 流式写入、实时同步 |
| 基本错误处理、脏数据记录 | 数据质量检查、数据转换 |
| CustomProcessor自定义索引请求 | DeleteByQuery清空索引 |

#### MVP最小可用范围
**功能**：
- 支持从MySQL读取数据写入ES8
- 支持Index（追加）、Upsert（覆盖）两种写入模式
- 支持基础认证（用户名/密码）
- 支持批量写入（默认5000条/批次）
- 支持基本的脏数据处理（记录到文件）
- 支持基本类型（text/keyword/long/double/date/boolean）
- 支持nested类型（兼容ES6实现）
- 支持vector类型（ES8向量搜索）

**性能**：
- 单线程写入≥5000条/秒
- 支持多线程并发（最多5个线程）

**可靠性**：
- 失败自动重试3次
- 脏数据数量达到阈值时中止任务（默认100条）

### 2.2 核心功能（P0）

#### F1: 数据源支持 `P0` `已确认`

**功能描述**
ES8 Writer插件作为DataX的Writer插件，需要能够接收来自多种Reader插件的数据，并写入到ES8集群。插件必须适配DataX的数据交换框架，正确处理数据类型转换。

**输入**
| 输入项 | 说明 | 约束 |
|-------|------|------|
| 来自Reader的数据记录 | DataX标准Record对象，包含多个Column | 必须符合DataX插件规范 |
| 字段类型信息 | 每个字段的数据类型（STRING/LONG/DOUBLE/DATE/BOOLEAN/OBJECT） | 必须提供 |
| 字段名称列表 | ES8索引的字段名称列表 | 不能为空，不能包含ES8保留字段 |

**处理**
1. 接收DataX Reader传递的Record对象
2. 遍历Record中的每一列（Column）
3. 根据配置的字段映射关系，将Column数据转换为ES8文档字段
4. 支持的数据类型转换（兼容ES6实现）：
   - STRING → ES8 text/keyword
   - LONG → ES8 long
   - DOUBLE → ES8 double
   - DATE → ES8 date
   - BOOLEAN → ES8 boolean
   - OBJECT → ES8 object（嵌套对象）
   - STRING/OBJECT → ES8 dense_vector（向量类型，配置中指定type为dense_vector）
5. 构建ES8 IndexRequest对象（Upsert模式也使用index方法，指定id）

**输出**
| 输出项 | 说明 |
|-------|------|
| ES8文档对象 | 符合ES8索引映射的JSON文档 |
| 写入结果统计 | 成功条数、失败条数、总条数 |

**业务规则**
| 规则ID | 规则描述 |
|--------|---------|
| R1.1 | 当输入字段类型为DATE时，必须提供日期格式（默认：yyyy-MM-dd HH:mm:ss） |
| R1.2 | 当输入字段值为NULL时，根据配置决定是写入null或跳过该字段 |
| R1.3 | 当字段映射表中类型为空且allowIndexNotExist=true时，自动推断字段类型 |
| R1.4 | 支持nested类型，兼容ES6插件的嵌套对象实现 |
| R1.5 | 支持vector类型，当配置type为dense_vector时，将STRING（JSON数组格式）或OBJECT转换为向量 |
| R1.6 | vector字段必须配置dims参数（向量维度），且所有向量维度必须一致 |
| R1.7 | Upsert模式使用client.index()方法，通过指定文档_id实现覆盖或创建 |

**验收标准（三段式）**

| 验证阶段 | 验收条件 |
|:--------:|---------|
| 【输入验证】 | AC1.1: 输入数据记录必须包含配置的所有字段，缺失字段应记录错误 |
| 【处理验证】 | AC1.2: 数据类型转换必须正确，STRING→text、LONG→long、DATE→date转换成功率100% |
| 【输出验证】 | AC1.3: 输出的ES8文档必须符合索引映射，nested对象和vector字段结构必须正确 |

#### F2: 写入模式 `P0` `已确认`

**功能描述**
插件需要支持两种标准写入模式和一种自定义处理模式：
- **Index模式**：追加新文档，文档ID不存在时创建，存在时覆盖
- **Upsert模式**：智能更新，文档ID不存在时创建，存在时更新部分字段
- **CustomProcessor模式**：用户自行构造索引请求，实现自定义写入逻辑

**输入**
| 输入项 | 说明 | 约束 |
|-------|------|------|
| 写入模式 | index/upsert/custom_processor | 必选，默认index |
| 文档主键字段 | 用于生成ES8文档_id的字段名 | Upsert模式必选 |
| 自定义处理器类名 | custom_processor模式下指定的处理器类名 | custom_processor模式必选 |

**处理**
1. **Index模式**：
   - 根据配置的主键字段生成文档ID
   - 调用ES8的`client.index()`方法
   - 如果指定了ID且ID已存在，则覆盖整个文档

2. **Upsert模式**：
   - 根据配置的主键字段生成文档ID
   - 同样使用`client.index()`方法，指定文档_id
   - 如果ID不存在，创建新文档；如果ID已存在，覆盖整个文档
   - **说明**：ES8的index方法在指定ID时，本身就具备upsert语义（不存在则创建，存在则覆盖）

3. **CustomProcessor模式**：
   - 加载用户指定的处理器类
   - 调用处理器的`process()`方法，由用户自行构造IndexRequest
   - 支持用户实现复杂的写入逻辑（如条件判断、数据转换等）

**输出**
| 输出项 | 说明 |
|-------|------|
| 写入结果 | 包含created/updated/skipped计数 |
| 错误信息 | 写入失败的详细原因 |

**业务规则**
| 规则ID | 规则描述 |
|--------|---------|
| R2.1 | Index模式下，如果文档ID已存在且配置为"冲突时报错"，则拒绝写入并记录错误 |
| R2.2 | Upsert模式下，必须配置主键字段，否则无法判断文档是否存在 |
| R2.3 | CustomProcessor模式下，用户必须实现指定的接口，否则任务启动失败 |
| R2.4 | CustomProcessor模式必须在安全环境下使用，避免执行任意代码 |

**验收标准（三段式）**

| 验证阶段 | 验收条件 |
|:--------:|---------|
| 【输入验证】 | AC2.1: 写入模式必须是index/upsert/custom_processor之一，否则拒绝启动任务 |
| 【处理验证】 | AC2.2: Index模式写入1000条数据，created计数必须≥0，updated计数必须=0 |
| 【输出验证】 | AC2.3: Upsert模式重复写入相同ID的数据，第二次必须更新而非创建，updated计数≥1 |

#### F3: 认证与连接 `P0` `已确认`

**功能描述**
插件需要支持ES8集群的认证和连接管理，包括基础认证、多节点高可用连接、连接池配置等。

**输入**
| 输入项 | 说明 | 约束 |
|-------|------|------|
| ES8集群地址 | 一个或多个ES8节点的HTTP地址，格式：host:port | 必选，支持多个（逗号分隔） |
| 用户名 | 用于基础认证的用户名 | 如果启用认证则必选 |
| 密码 | 用于基础认证的密码 | 如果启用认证则必选 |
| 连接超时 | 建立连接的超时时间（秒） | 可选，默认30s |
| Socket超时 | 读取数据的超时时间（秒） | 可选，默认60s |
| 连接池大小 | 最大连接数 | 可选，默认10 |

**处理**
1. 使用ES8 Java API Client的`RestClientBuilder`创建客户端
2. 配置基础认证（如果提供用户名密码）：
   ```java
   final CredentialsProvider credentialsProvider = new BasicCredentialsProvider();
   credentialsProvider.setCredentials(AuthScope.ANY,
       new UsernamePasswordCredentials(username, password));
   ```
3. 配置多节点HttpHost列表，实现客户端负载均衡
4. 配置连接池和超时参数
5. 创建ElasticsearchClient和ElasticsearchAsyncClient（用于异步操作）

**输出**
| 输出项 | 说明 |
|-------|------|
| ES8客户端 | ElasticsearchClient对象，用于后续所有ES8操作 |
| 连接状态 | 连接成功或失败的详细信息 |

**业务规则**
| 规则ID | 规则描述 |
|--------|---------|
| R3.1 | 当提供多个节点地址时，客户端会轮询使用这些节点，实现高可用 |
| R3.2 | 连接失败时，应该重试3次，每次间隔1秒，3次都失败后报错并中止任务 |
| R3.3 | 密码不能明文打印到日志中，必须使用****替代 |
| R3.4 | 如果用户名密码为空，则不使用认证（适用于测试环境） |

**验收标准（三段式）**

| 验证阶段 | 验收条件 |
|:--------:|---------|
| 【输入验证】 | AC3.1: ES8集群地址不能为空，格式必须为host:port，端口号范围1024-65535 |
| 【处理验证】 | AC3.2: 使用错误的用户名密码连接时，必须在60秒内返回认证失败错误 |
| 【输出验证】 | AC3.3: 连接成功后，调用`client.cluster.health()`必须返回green或yellow状态 |

#### F4: 字段映射 `P0` `已确认`

**功能描述**
插件需要支持灵活的字段映射功能，包括自定义映射、自动推断（可配置）、嵌套对象等。

**输入**
| 输入项 | 说明 | 约束 |
|-------|------|------|
| 字段映射配置 | 源字段名→目标字段名的映射关系 | 可选，默认同名映射 |
| 字段类型配置 | 每个字段的目标ES8类型 | 可选，默认自动推断 |
| 自动推断开关 | 是否启用自动类型推断 | 可选，默认false（关闭） |
| 嵌套对象分隔符 | 用于创建嵌套对象的分隔符，如点号（.） | 可选，默认不创建嵌套对象 |

**处理**
1. **自动类型推断**（基于allowIndexNotExist参数）：
   - 当字段映射表中类型为空且allowIndexNotExist=true时，根据DataX Column的Type自动推断ES8类型
   - 当字段映射表中类型为空且allowIndexNotExist=false时，所有字段默认为text类型
   - 当字段映射表中指定了类型时，使用指定类型
   - 内置映射规则：
     ```
     STRING → text（包含keyword子字段）
     LONG → long
     DOUBLE → double
     DATE → date（格式：yyyy-MM-dd HH:mm:ss）
     BOOLEAN → boolean
     OBJECT → object（嵌套对象）
     ```

2. **自定义字段映射**：
   - 读取配置的映射关系，如：`user_name → name`
   - 支持常量值：`"constant_value" → field`
   - 支持表达式：`${timestamp} → create_time`

3. **嵌套对象**（兼容ES6实现）：
   - 如果字段名包含分隔符（如`user.address.city`），则创建嵌套对象
   - 示例：源字段`city`映射到`user.address.city`，会创建嵌套文档
   - 支持nested类型（参考ES6插件实现）

4. **向量类型**（ES8新特性）：
   - 支持dense_vector类型，用于向量搜索和AI应用
   - 当配置type为dense_vector时，将STRING（JSON数组格式）或OBJECT转换为向量
   - 示例STRING格式：`"[0.1, 0.2, 0.3]"`
   - 示例OBJECT格式：Map或List结构
   - 必须配置dims参数（向量维度），所有向量维度必须一致
   - 示例配置：{"name": "embedding", "type": "dense_vector", "dims": 768}

**输出**
| 输出项 | 说明 |
|-------|------|
| ES8文档 | 包含正确字段名和类型的JSON文档 |
| 映射关系 | 实际应用的映射关系（用于日志和调试） |

**业务规则**
| 规则ID | 规则描述 |
|--------|---------|
| R4.1 | 当源字段在映射配置中不存在时，默认使用同名映射 |
| R4.2 | 当多个源字段映射到同一个目标字段时，后者覆盖前者，并记录警告 |
| R4.3 | 嵌套对象深度不超过3层，超过时记录错误并跳过该字段 |
| R4.4 | 日期类型字段必须提供格式，默认使用`yyyy-MM-dd HH:mm:ss` |
| R4.5 | 当字段映射表中类型为空且allowIndexNotExist=true时，自动推断类型；为空且allowIndexNotExist=false时，使用text类型 |
| R4.6 | vector字段必须配置dims参数，且所有向量维度必须一致 |
| R4.7 | vector字段值当源类型为STRING时，必须是JSON数组格式（如"[0.1, 0.2, 0.3]"） |

**验收标准（三段式）**

| 验证阶段 | 验收条件 |
|:--------:|---------|
| 【输入验证】 | AC4.1: 字段映射配置的格式必须为"源字段:目标字段"，每行一个映射 |
| 【处理验证】 | AC4.2: allowIndexNotExist=false时，所有字段必须是text类型 |
| 【输出验证】 | AC4.3: 映射后的ES8文档字段名必须与配置一致，嵌套对象和vector字段结构必须正确 |

#### F5: 索引管理 `P0` `已确认`

**功能描述**
插件需要在写入前检查索引是否存在，不存在时根据配置决定是否自动创建；支持在写入前清空索引（可配置）。索引名称支持pattern表达式（如`index-{format}`）。

**输入**
| 输入项 | 说明 | 约束 |
|-------|------|------|
| 索引名称 | ES8目标索引名称，支持pattern表达式 | 必选 |
| 允许索引不存在 | 索引不存在时是否允许（触发类型推断） | 布尔值，默认true |
| 自动创建索引 | 索引不存在时是否自动创建 | 布尔值，默认true |
| 清空索引 | 写入前是否清空索引 | 布尔值，默认false |
| 索引映射配置 | 创建索引时的mapping配置 | 可选，自动推断 |
| 索引配置 | 索引的settings配置（分片数、副本数等） | 可选 |

**处理**
1. **检查索引是否存在**：
   ```java
   boolean exists = client.indices().exists(e -> e.index(indexName)).value();
   ```

2. **处理索引名称pattern表达式**：
   - 如果索引名称包含pattern表达式（如`index-{format}`），直接判定索引不存在
   - 当索引包含pattern时，即使autoCreateIndex=true，也不会触发自动创建
   - 当索引包含pattern时，直接抛出异常提示用户索引名称不合法或需要手动创建

3. **自动创建索引**（可配置）：
   - 如果autoCreateIndex=true且索引不存在且无pattern，则调用`client.indices().create()`
   - 如果autoCreateIndex=false且索引不存在，则报错并中止任务
   - 根据字段类型自动生成mapping
   - 设置默认settings（如分片数=3，副本数=1）

4. **清空索引**（可配置）：
   - 如果cleanUp=true，直接调用`client.indices().delete()`删除整个索引
   - 然后调用`client.indices().create()`重新创建索引
   - **注意**：不使用deleteByQuery，性能问题
   - 在日志中记录清空前的文档数量

**输出**
| 输出项 | 说明 |
|-------|------|
| 索引状态 | 已存在/已创建/已清空 |
| 索引信息 | 分片数、文档数、存储大小 |

**业务规则**
| 规则ID | 规则描述 |
|--------|---------|
| R5.1 | 当索引名称包含pattern表达式（如`{format}`）时，直接抛出异常，不支持自动创建 |
| R5.2 | 当索引不存在且autoCreateIndex=false时，报错并中止任务 |
| R5.3 | 清空索引操作不可逆，使用delete+create而非deleteByQuery |
| R5.4 | autoCreateIndex配置缺失时，默认值为true（自动创建） |
| R5.5 | cleanUp配置缺失时，默认值为false（不清空） |
| R5.6 | allowIndexNotExist用于控制是否允许索引不存在，与字段类型推断相关 |

**验收标准（三段式）**

| 验证阶段 | 验收条件 |

| 【输入验证】 | AC5.1: 索引名称必须符合ES8命名规范，不能以-、_开头，不能包含大写字母；如果包含pattern表达式如{format}，则抛出异常 |

### 2.3 性能优化（P0）

#### F6: 性能优化 `P0` `已确认`

**功能描述**
插件需要提供多种性能优化手段，满足大规模数据同步的性能要求。

**功能列表**
1. **批量写入**：默认1000条/批次（ES8推荐值），可配置
2. **多线程并发**：最多5个并发线程，每个线程独立处理一个批次
3. **失败重试**：支持配置重试次数和重试间隔
4. **限流**：使用Exchangis增强DataX的限流能力（core.transport.channel.speed.byte和core.transport.channel.speed.record）

**输入**
| 输入项 | 说明 | 约束 |
|-------|------|------|
| 批量大小 | 每批次的文档数量 | 范围：100-50000，默认1000 |
| 并发线程数 | 同时写入的线程数 | 范围：1-10，默认1 |
| 重试次数 | 失败后的重试次数 | 范围：0-10，默认3 |
| 重试间隔 | 重试之间的等待时间（毫秒） | 范围：100-10000，默认1000 |

**处理**
1. **批量写入**：
   - 使用ES8 Java API Client的`BulkIngester`实现批量写入
   - BulkIngester自动管理批量大小和并发
   - 配置初始批量大小1000，最大并发5个批量请求
   - 任务结束时自动刷新剩余未提交的数据

2. **多线程并发**：
   - 使用DataX的`AbstractTask`的并发机制
   - 每个线程处理数据的一个分片
   - 每个线程独立创建ES8客户端（线程安全）

3. **失败重试**：
   - 捕获ES8的异常（如429 Too Many Requests）
   - 指数退避策略：第1次重试等待1秒，第2次等待2秒，第3次等待4秒
   - 3次都失败后记录脏数据并继续下一条

4. **限流**（使用Exchangis能力）：
   - 依赖Exchangis的core.json配置参数：
     - `core.transport.channel.speed.byte`：字节速率限制
     - `core.transport.channel.speed.record`：记录速率限制
   - 插件本身不实现限流逻辑，由Exchangis框架统一控制

**输出**
| 输出项 | 说明 |
|-------|------|
| 性能统计 | 总条数、总耗时、平均TPS、峰值TPS |
| 重试统计 | 重试次数、重试成功率 |

**业务规则**
| 规则ID | 规则描述 |
|--------|---------|
| R6.1 | 批量大小不能超过ES8的`http.max_content_length`限制（默认100MB） |
| R6.2 | 并发线程数×批量大小不能超过ES8的索引缓冲区限制 |
| R6.3 | 429错误（Too Many Requests）必须自动重试，其他错误根据配置决定是否重试 |
| R6.4 | 限流功能由Exchangis框架提供，插件通过core.json参数控制 |
| R6.5 | 使用ES8 Java API Client的BulkIngester进行批量写入，配置初始批量大小1000，最大并发5个批量请求 |

**验收标准（三段式）**

| 验证阶段 | 验收条件 |
|:--------:|---------|
| 【输入验证】 | AC6.1: 批量大小必须在100-50000之间，并发线程数必须在1-10之间，否则使用默认值 |
| 【处理验证】 | AC6.2: 单线程批量写入10000条数据，耗时必须≤2秒（≥5000条/秒） |
| 【输出验证】 | AC6.3: 5个并发线程批量写入50000条数据，耗时必须≤5秒（≥10000条/秒） |

### 2.4 错误处理（P0）

#### F7: 错误处理 `P0` `已确认`

**功能描述**
插件需要具备完善的错误处理机制，包括脏数据记录、错误阈值中止（数量阈值）、统计信息上报等。

**功能列表**
1. **脏数据记录**：记录无法写入的数据，不落盘（内存中统计）
2. **错误阈值中止**：当错误记录数达到配置阈值时中止任务（仅数量阈值）
3. **统计信息上报**：每10秒自动上报一次统计信息到DataX

**输入**
| 输入项 | 说明 | 约束 |
|-------|------|------|
| 错误阈值记录数 | 错误记录数达到此值时中止任务 | 范围：10-10000，默认100 |
| 最大脏数据条数 | 脏数据内存中最大记录数 | 范围：1000-1000000，默认100000 |

**处理**
1. **脏数据记录**（不落盘）：
   - 捕获写入失败的记录
   - 在内存中记录原始数据、错误原因、时间戳
   - 脏数据不写入文件，仅在内存中统计

2. **错误阈值中止**（仅数量阈值）：
   - 实时统计错误记录数
   - 当错误记录数≥配置阈值时，立即中止任务
   - 中止前记录详细统计信息
   - **不支持百分比阈值**

3. **统计信息上报**：
   - 每10秒自动上报一次统计信息（DataX框架自动触发）
   - 调用DataX的`super.getTaskPluginCollector().collectMessage()`上报统计信息
   - 任务结束时上报最终统计

**输出**
| 输出项 | 说明 |
|-------|------|
| 任务统计 | 总条数、成功条数、失败条数、跳过条数 |
| 脏数据统计 | 脏数据数量（内存中，不落盘） |
| 任务结果 | 成功/失败/部分成功 |

**业务规则**
| 规则ID | 规则描述 |
|--------|---------|
| R7.1 | 脏数据仅在内存中统计，不写入文件（不落盘） |
| R7.2 | 当错误记录数达到阈值时，必须立即中止任务，不能再处理下一条数据 |
| R7.3 | 脏数据统计包含：timestamp、raw_data、error_message、error_type |
| R7.4 | 任务结束时，无论成功失败，都必须上报最终统计信息 |
| R7.5 | 不支持错误百分比阈值，仅支持错误数量阈值 |
| R7.6 | 统计信息每10秒自动上报一次，调用collectMessage()方法 |

**验收标准（三段式）**

| 验证阶段 | 验收条件 |
|:--------:|---------|
| 【输入验证】 | AC7.1: 错误阈值记录数必须在10-10000之间，否则使用默认值100 |
| 【处理验证】 | AC7.2: 人为制造10条脏数据，脏数据统计必须包含这10条记录，且字段完整（不落盘） |
| 【输出验证】 | AC7.3: 设置错误阈值为100条，处理1000条数据，前100条失败后，任务必须立即中止 |

### 附录C：与ES6插件对比

| 对比项 | ES6插件 | ES8插件 |
|-------|---------|---------|
| 客户端版本 | elasticsearch-rest-high-level-client 6.7.1 | elasticsearch-java-client 8.16.1 |
| 包路径 | com.webank.wedatasphere.exchangis.datax.plugin.writer.elasticsearchwriter.v6 | com.webank.wedatasphere.exchangis.datax.plugin.writer.elasticsearchwriter.v8x |
| Maven模块 | datax-elasticsearchwriter | datax-elasticsearch8xwriter（独立模块） |
| 认证方式 | 基础认证 | 基础认证（相同） |
| 写入模式 | Index/Upsert | Index/Upsert/CustomProcessor（新增） |
| 数据类型 | 基本类型 + nested | 基本类型 + nested/object/vector（新增vector） |
| 索引管理 | 清空索引（cleanup） | 清空索引（cleanUp使用delete+create）+ pattern表达式检测 |
| 类型推断 | 默认开启 | 基于allowIndexNotExist参数控制（默认true） |
| 批量大小 | 默认1000 | 默认1000（ES8推荐值，相同） |
| 性能目标 | 未明确 | 单线程≥5000条/秒，多线程≥10000条/秒（明确） |
| 错误处理 | 基本错误处理 | 增强错误处理（数量阈值、脏数据不落盘） |
| 限流 | 插件自行实现 | 使用Exchangis框架能力（core.transport.channel.speed） |
| 依赖隔离 | 无 | 完全隔离（使用Maven Shade） |
| 版本支持 | ES 6.x | ES 8.0.x所有子版本（8.0-8.16.1+） |
