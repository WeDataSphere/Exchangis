## 一、需求概述 【核心】

### 1.1 业务背景

在企业数据同步场景中,常见的需求是将数据从源表同步到目标表时,需要为某些字段填充固定值。典型场景包括:

1. **数据来源标识**: 目标表需要记录数据来源系统标识(如 `source_system = 'CRM'`)
2. **批次标记**: 标记数据同步批次(如 `batch_id = '202501'`)
3. **默认值填充**: 源表缺少某些字段,需要在目标表填充默认值

**当前痛点**: 用户只能借用冗余字段配合转换函数实现,操作繁琐且易出错。

### 1.2 核心目标

提供字段映射静态值配置能力,允许用户在配置数据同步任务时,直接为目标表字段指定固定值,无需源表对应字段。

**成功指标**:
- 用户可在字段映射界面配置静态值字段
- 配置的静态值可正确持久化和加载
- DataX任务执行时正确将静态值写入目标字段

### 1.3 项目上下文

**项目类型**: 现有项目（Exchangis数据交换平台）

**相似功能检查**:
- 现有模块: `FieldMappingColumn`、`ColumnDefine` 已支持source/sink字段映射
- 现有模块: `ColumnDefine.value` 字段已预留静态值属性（后端已部分支持）

**依赖的现有模块**:
- `SubExchangisJob.ColumnDefine` - 列定义类（已有value属性）
- `DataxExchangisEngineJobBuilder` - DataX任务构建器

### 1.4 边界定义

| 包含（In Scope） | 不包含（Out of Scope） |
|-----------------|----------------------|
| 支持配置多个静态值字段 | 动态值支持（日期函数、UUID等） |
| 配置正确持久化和加载 | Sqoop引擎支持（后续迭代） |
| DataX Reader端通过SQL实现静态值注入 | 非TiDB/TDSQL数据源支持（后续扩展） |
| 配置时校验目标字段存在性 | 自定义新增目标表字段 |
| 目标字段映射唯一性校验 | 复杂表达式计算 |
| | 前端界面交互流程改造 |
| | 静态值历史版本管理 |

### 2.2 功能点1: 配置持久化与加载 【F1】

**功能描述**: 将用户配置的静态值字段正确保存到数据库,并在编辑时正确回显。

**输入**:
- 用户配置的字段映射列表（包含静态值映射）
- 作业ID

**输出**:
- 配置持久化到数据库
- 编辑时正确加载和回显静态值配置

**业务规则**:

| 规则ID | 规则描述 |
|--------|---------|
| R1.1 | 静态值存储在字段映射JSON的`static_value`字段 |
| R1.2 | 映射类型存储在`mapping_type`字段,值为"NORMAL"或"STATIC" |
| R1.3 | 加载时根据`mapping_type`判断渲染方式 |
| R1.4 | NULL静态值表示没有静态值,不写入目标字段 |
| R1.5 | 静态值不能为空字符串,允许空格但trim后不能为空 |
| R1.6 | 同一目标字段只能有一个映射（源字段映射或静态值映射,不可重复） |

**数据存储结构**:

```json
{
  "type": "MAPPING",
  "mapping": [
    {
      "source_field_name": "order_id",
      "source_field_type": "BIGINT",
      "sink_field_name": "order_id",
      "sink_field_type": "BIGINT",
      "mapping_type": "NORMAL"
    },
    {
      "source_field_name": null,
      "source_field_type": null,
      "sink_field_name": "source_system",
      "sink_field_type": "VARCHAR",
      "static_value": "CRM",
      "mapping_type": "STATIC"
    }
  ]
}
```

**优先级**: P0

---

### 2.3 功能点2: DataX Reader静态值注入 【F2】

**功能描述**: DataX任务构建时,在Reader端的SQL查询中注入静态值,使其作为查询结果的一部分传递给Writer。

**实现原理**:
对于MySQL/TiDB Reader,DataX通过将column配置转换为SQL的SELECT子句来读取数据。静态值通过在SELECT中添加常量表达式实现。

**输入**:
- 包含静态值映射的作业配置
- 源表和目标表元数据

**输出**:
- DataX任务JSON配置（静态值在Reader的column中）
- 任务执行时静态值正确写入目标表

**业务规则**:

| 规则ID | 规则描述 |
|--------|---------|
| R2.1 | 静态值字段在DataX Reader的column配置中使用常量表达式 |
| R2.2 | 静态值通过SQL SELECT语句中的常量实现,如 `'CRM' as source_system` |
| R2.3 | Writer端column按顺序与Reader输出对应,无需特殊处理 |
| R2.4 | 类型不匹配时,DataX运行时自动转换,转换失败则报错 |

**DataX配置示例**:

假设源表`orders`有字段`order_id`、`amount`,目标表需要额外的`source_system`字段填充固定值'CRM'。

```json
{
  "content": [{
    "reader": {
      "name": "mysqlreader",
      "parameter": {
        "connection": [{
          "table": ["orders"],
          "jdbcUrl": ["jdbc:mysql://source-host:3306/source_db"]
        }],
        "column": [
          "order_id",
          "amount",
          "'CRM' as source_system"
        ],
        "username": "reader_user",
        "password": "xxx"
      }
    },
    "writer": {
      "name": "mysqlwriter",
      "parameter": {
        "connection": [{
          "table": ["orders_target"],
          "jdbcUrl": "jdbc:mysql://target-host:3306/target_db"
        }],
        "column": [
          "order_id",
          "amount",
          "source_system"
        ],
        "username": "writer_user",
        "password": "xxx"
      }
    }
  }]
}
```

**生成的SQL语句**:

DataX mysqlreader会将上述column配置转换为如下SQL:

```sql
SELECT order_id, amount, 'CRM' as source_system FROM orders
```

执行结果示例:

| order_id | amount | source_system |
|----------|--------|---------------|
| 1001 | 100.00 | CRM |
| 1002 | 200.00 | CRM |
| 1003 | 150.00 | CRM |

**多个静态值字段示例**:

```json
{
  "reader": {
    "name": "mysqlreader",
    "parameter": {
      "column": [
        "order_id",
        "amount",
        "'CRM' as source_system",
        "'202501' as batch_id",
        "1 as is_synced"
      ]
    }
  },
  "writer": {
    "name": "mysqlwriter",
    "parameter": {
      "column": [
        "order_id",
        "amount",
        "source_system",
        "batch_id",
        "is_synced"
      ]
    }
  }
}
```

**生成的SQL**:

```sql
SELECT order_id, amount, 'CRM' as source_system, '202501' as batch_id, 1 as is_synced FROM orders
```

**优先级**: P0

## 四、数据需求 【重要】

### 4.1 数据模型变更

本次需求**不需要新增数据库表**,仅扩展现有字段映射JSON结构。

**字段映射JSON扩展**:

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|:----:|------|
| mapping_type | String | 是 | 映射类型: NORMAL(源字段映射), STATIC(静态值映射) |
| static_value | String | 否 | 静态值,仅mapping_type=STATIC时有效 |

### 4.2 现有实体扩展

**ColumnDefine类** (已有value属性,无需修改):

```
SubExchangisJob.ColumnDefine
├── name: String       // 字段名
├── type: String       // 字段类型
├── rawType: String    // 原始类型
├── index: Integer     // 字段索引
└── value: Object      // 静态值 (已存在)
```

### 4.3 数据规模预估

| 指标 | 预估值 |
|-----|:------:|
| 单作业静态值字段数 | **1-5** 个 |
| 静态值长度 | **1-500** 字符 |
| 对存储影响 | **极小**,JSON字段扩展 |

## 五、验收标准 【核心】

### 功能点1验收标准（配置持久化与加载）

- [ ] AC1.1: 保存包含静态值的作业配置,数据库正确存储`static_value`和`mapping_type`
- [ ] AC1.2: 重新编辑作业,静态值配置正确回显
- [ ] AC1.3: 修改静态值后保存,数据库正确更新
- [ ] AC1.4: 删除静态值映射行后保存,数据库正确移除该配置
- [ ] AC1.5: 旧版不含`mapping_type`的配置正常加载,默认视为NORMAL类型

### 功能点2验收标准（DataX Reader静态值注入）

- [ ] AC2.1: 执行包含静态值的DataX任务,Reader端SQL正确包含静态值常量表达式
- [ ] AC2.2: 目标表对应字段写入配置的固定值
- [ ] AC2.3: 所有同步记录的静态值字段均正确写入,值一致
- [ ] AC2.4: 支持配置多个静态值字段,SQL中正确包含所有常量
- [ ] AC2.5: 静态值类型转换失败时,任务报错并输出明确错误信息

## 六、非功能需求 【重要】

### 6.1 性能需求

| 指标 | 要求 |
|-----|------|
| 字段映射加载 | 增加静态值解析,响应时间增加 ≤ **50ms** |
| 任务构建 | 静态值处理对构建耗时影响 ≤ **10ms** |
| 任务执行 | 静态值写入不影响整体同步性能 |

### 6.2 兼容性需求

| 指标 | 要求 |
|-----|------|
| 旧版配置兼容 | 不含`mapping_type`字段的旧配置,默认视为NORMAL类型 |
| API兼容 | 接口参数扩展,旧参数仍可正常使用 |

### 6.3 可维护性需求

- 静态值配置变更需记录操作日志
- 任务执行日志中包含静态值字段信息
- 错误信息明确指出具体字段和原因
